# DESIGN.md — dsh-session-search

## Product / Purpose

- **Назначение:** Предоставление автономному агенту Ди (Dee) специализированного инструмента (`session_search`) для полнотекстового поиска по истории прошлых сессий DeepSeek Harness через штатный движок ядра `ctx.sessionQuery`.
- **Аудитория:** Автономный агент Ди (Dee), пользователи DSH, сценарии контекстного воспоминания уроков, поиска прошлых решений и архитектурных ответов.
- **Статус:** Active (Public DSH plugin release).

## User Surfaces

- **Web/UI:** UI отсутствует на текущем этапе — плагин полностью **host-only**, клиентских компонентов (React/JSX) и CSS нет.
- **DSH UI / settings / slots:** Слоты интерфейса не регистрируются. Конфигурация плагина осуществляется через схему `Config` Cordis:
  - `maxResults` (number, default: 20): Базовый лимит возвращаемых сессий при поиске.
  - `snippetLength` (number, default: 200): Максимальная длина текстового фрагмента вокруг совпадения.
  - `timeoutMs` (number, default: 30000): Защитный таймаут ожидания ответа движка сессий (мс).
- **API / Model Tools:**
  - Зарегистрированный инструмент агента: `session_search`.
  - Свойства инструмента: `timeoutMs: 30000`, `isConcurrencySafe: () => true`.
  - Язык интерфейса инструмента: канонический английский (согласно стандарту публичных плагинов DSH).
  - Входные параметры:
    - `query` (string, required): Поисковые термы/запрос (обязательная непустая строка).
    - `limit` (integer, optional): Максимум результатов (валидируется и зажимается в диапазон `1..100`, по умолчанию `maxResults`).
  - Формат вывода модели:
    - Успешный результат: список строк вида:
      ```text
      • <Title> [<SessionId>] (<YYYY-MM-DD>)
        <Snippet совпадения>
      ```
      (если сниппет пустой, перенос строки не добавляется).
      При наличии курсора следующей страницы добавляется строка:
      ```text
      (more results available — refine your query)
      ```
    - Пустой результат:
      ```text
      session_search: no matches found.
      ```
    - Ошибка валидации или исполнения движка:
      ```text
      session_search: error: <текст ошибки>
      ```
- **CLI:** Управление через `dsh plugin` и пакетный менеджер `pnpm`.
- **Документация:**
  - `README.md` — каноническое английское руководство;
  - `README.zh.md` — китайское руководство (обязательно для публичных плагинов);
  - `README.ru.md` — русскоязычное руководство;
  - `docs/design/DESIGN.md` — дизайн-контракт проекта.

## Architecture & Integration

- **Cordis Service Injection:** Плагин объявляет зависимости `export const inject = ['tools', 'sessionQuery']`.
- **Жизненный цикл:** Регистрация инструмента завернута в `ctx.effect(() => ctx.tools.register(...))` для гарантированной отмены эффектов при выгрузке/перезапуске плагина.
- **Имя и идентичность:**
  - `package.json`: `@goodandready/dsh-session-search`;
  - `cordis.patch.yml`: регистрация в бандле под именем `@goodandready/dsh-session-search`;
  - `lib/index.js`: `export const name = 'dsh-session-search'` (краткое внутреннее имя плагина в контексте Cordis).
- **Zero Heavy Overhead:** Плагин не запускает собственный FTS-индекс и не распаковывает архивы `.jsonl.zstd` в оперативную память. Он полностью делегирует поиск штатному сервису ядра `@deepseek-ai/dsh-session-query` (SQLite FTS5), обеспечивая минимальное потребление ресурсов и высокую скорость ответа.

## Key Decisions (ADR)

### ADR-001: Язык строк инструмента в приватной версии (Archived / Superseded)
- **Дата:** 2026-09-17
- **Статус:** Superseded by ADR-002
- **Суть:** В приватной версии строки были зафиксированы на русском языке под внутренний промпт агента.

### ADR-002: Переход на публичный маршрут и канонический английский язык инструмента
- **Дата:** 2026-09-17
- **Статус:** Accepted
- **Контекст:** Переход плагина на публичный маршрут `@goodandready/dsh-session-search` для публикации в открытом реестре npmjs.
- **Решение:**
  1. В соответствии со стандартом `dhs-plugin-release-workflow`, каноническим языком всех DSH-плагинов в коде, схемах инструментов, описаниях параметров и системных ответах является английский (`en`).
  2. Строки `session_search` переведены на чистый английский язык (`session_search: no matches found.`, `session_search: error: ...`, `(more results available — refine your query)`).
  3. Плагин host-only, клиентских UI-слотов нет, поэтому регистрация клиентской локали `locale.register` не требуется.
  4. Документация оформлена на трёх языках: английский (`README.md`), китайский (`README.zh.md`) и русский (`README.ru.md`).

### ADR-003: Харденинг инструмента session_search (Lifecycle, валидация, дата и таймауты)
- **Дата:** 2026-09-24
- **Статус:** Accepted (Реализация задач аудита #11, #12, #13)
- **Контекст:** По результатам глубокого аудита кодовой базы выявлены риски: утечка эффекта при hot-reload без `ctx.effect`, зависание без `timeoutMs`, поиск слова "undefined" при пустом вводе и отсутствие даты сессий в результатах.
- **Решение:**
  1. Регистрация `ctx.tools.register` обёрнута в `ctx.effect(() => ...)` с возвратом диспозера для чистого жизненного цикла Cordis.
  2. Объявлен `timeoutMs: 30000` (настраивается через `Config.timeoutMs`) и флаг `isConcurrencySafe: () => true`.
  3. Введена строгая валидация `args.query`: пустые строки, пробелы и значения без текста пресекаются до вызова FTS движка с сообщением `session_search: error: query must be a non-empty string.`.
  4. Формат вывода обогащён компактной датой сессии: `• ${title} [${id}] (${dateStr})` на основе `header.updated_at` / `header.created_at` / `bestMatch.time`.
  5. Сниппет форматируется аккуратно (без висячих `\n  ` при пустом сниппете) и обрезается до настраиваемого `snippetLength` (по умолчанию 200).

### ADR-004: Клиентская карточка настроек, продуктовый allowlist и политика обновлений (Issues #15, #16, #17)
- **Дата:** 2026-09-26
- **Статус:** Accepted
- **Контекст:** По результатам проверки #15, #16, #17: в npm артефакт ошибочно попадали тестовые файлы, конфигурационные параметры не имели графической поверхности в DSH Web UI, и отсутствовала явная фиксация политики обновлений.
- **Решение:**
  1. **Продуктовый артефакт (Issue #15):** В `package.json` поле `files` ограничено строгим списком релизных файлов (`lib`, `cordis.patch.yml`, `README.md`, `README.ru.md`, `README.zh.md`, `LICENSE`). Каталог `test/` исключён из распространяемого npm-пакета.
  2. **Поверхность настроек (Issue #16):** Реализован нативный клиентский модуль `lib/client.js` (`@goodandready/dsh-session-search`), регистрирующий карточку конфигурации в слотах `plugins.row.config`, `settings.plugin.item` и `plugins.item`. Пользователь может настраивать `maxResults` (1..100), `snippetLength` (50..1000) и `timeoutMs` (1000..120000) прямо в интерфейсе DSH с валидацией диапазонов и сохранением через `ctx.settingsScope`.
  3. **Интеграция настроек на хосте:** `lib/index.js` подписывается на сервис `settings` через `ctx.inject(['settings'], ...)` с динамическим чтением параметров при каждом вызове `session_search`.
  4. **Политика обновлений (Issue #17):** Зафиксировано и отображается в карточке, что обновления плагина осуществляются через пакетный менеджер и CLI `dsh` (`dsh plugin --profile web add @goodandready/dsh-session-search@latest`), исключая создание неподдерживаемых браузерных авто-апдейтеров.

### ADR-005: Явное объявление Cordis inject в клиентском модуле (Issue #19)
- **Дата:** 2026-09-27
- **Статус:** Accepted
- **Контекст:** В версии 0.1.6 клиентский модуль `lib/client.js` обращался к сервисам `ctx.locale` и `ctx.slots`, но не объявлял `exports.inject = ['slots', 'locale']`. Без явного объявления зависимостей Cordis клиентский модуль мог запускаться до готовности сервисов, вызывая сбои и каскадную задержку зависимых компонентов Web UI (включая `dsh-client-ui-conversation` и экран чата).
- **Решение:**
  1. В `lib/client.js` добавлено явное объявление `exports.inject = ['slots', 'locale']` (и `module.exports.inject`).
  2. Регистрация локалей и слотов оформлена с проверкой `typeof ctx.effect === 'function'` и fallback на прямую регистрацию при отсутствии эффектора.
  3. В `test/identity.test.mjs` добавлен регрессионный тест на наличие объявления `inject` в клиентском модуле.

### ADR-006: Адаптация настроек под DSH 0.2.0+ и DSH Desktop (Issues #21, #22, #23, #24, #25, #26)
- **Дата:** 2026-10-09
- **Статус:** Accepted
- **Контекст:**
  1. В DSH Desktop и ядре 0.2.0-rc.2 валидатор `parseSettingsNamespace` требует `/^[a-z][a-z0-9-]*$/` и бросает фатальный `TypeError` на scoped-именах со слэшем `@.../...`, вызывая краш старта хоста (#26).
  2. В DSH 0.2.0+ объект `ctx.settingsScope` удалён из клиентского рантайма; настройки предоставляются через сервис `ctx.configForms` (#21, #23).
  3. Клиентская карточка при недоступности скоупа ложно рапортовала «Saved» вместо ошибки (#23).
  4. Сохранение настроек в ядре передаётся через событие `loader/volatile-update` (#22).
  5. Атрибут `data-dsh-plugin` на `<style>` содержал scoped-имя вместо короткого `ROW_ID` плагина (#25).
  6. В репозитории отсутствовал `CHANGELOG.md` (#24).
- **Решение:**
  1. На сервере (`lib/index.js`) регистрация настроек выполняется по короткому имени `dsh-session-search`, обёрнута в `try / catch` с логированием предупреждения в fallback и дополнена подпиской на событие `'loader/volatile-update'` для горячей синхронизации без перезапуска процесса.
  2. На клиенте (`lib/client.js`) `NS` установлен в `ROW_ID` (`dsh-session-search`). Поддержано извлечение скоупа через `ctx.configForms.get(ROW_ID)` с fallback на `ctx.settingsScope`, подписка на снапшоты, а при отсутствии скоупа кнопка сохранения выводит понятную ошибку.
  3. В `lib/client.js` объявлен `exports.inject = ['slots', 'locale', 'configForms']`.
  4. В `ensureStyles()` атрибут `data-dsh-plugin` переведён на `ROW_ID` (`dsh-session-search`).
  5. В корень репозитория добавлен `CHANGELOG.md` с историей всех версий и включён в `package.json.files`.

### ADR-007: Модернизация хост-сервиса настроек под DSH 0.2.0+ (Issue #29)
- **Дата:** 2026-10-15
- **Статус:** Accepted (Реализация задачи #29)
- **Контекст:** В ходе аудита кодовой базы выявлено, что ветка вызова `sctx.settings.register` в `lib/index.js` является мёртвой в рантайме DSH `0.2.0-rc.2+`, так как метод `register` в сервисе `settings` ядра отсутствует. Вызов перехватывался `try / catch`, из-за чего чтение конфигурации всегда откатывалось на исходный снимок `ctx.fiber?.config ?? config`.
- **Решение:**
  1. Вызов `sctx.settings.register` полностью удалён.
  2. Внедрена каноническая связка DSH 0.2.0+:
     - `sctx.settings.configure({ auto: false }, ctx.fiber)` для регистрации формы настроек плагина;
     - `sctx.settings.describe().find(row => row.ns === name)` для динамического считывания живых настроек;
     - `plainConfig` и `resolveConfig` для рекурсивного разворачивания боксов `VolatileRef`, функций и вложенных структур;
     - реактивная подписка на события `settings/document-updated`, `loader/volatile-update` и `internal/update`;
     - регистрация функций очистки диспозеров в `sctx.effect`.
  3. В тестовый набор добавлены модульные проверки работы `plainConfig`, контракта `configure`/`describe` и отсутствия устаревшего `settings.register`.
